# Capability Classification

Deliverable for backlog item P1-02. Each of the 11 original candidates was independently classified by the Architect against the 5-category model, then challenged by the Risk & Governance Reviewer. The Final Verdict column records the Reviewer's verdict after that independent challenge, not the Architect's initial self-assessment. Notably, every candidate's initial design — including the Architect's own — was found to need rework before it is build-ready: no candidate survives as a clean keep, cut, or merge as originally proposed.

| Capability | Layer | Classification | Final Verdict | Rationale |
|---|---|---|---|---|
| Stewardship Agent Architect | Factory | Specialised AI agent | redesign | Architect argued for keeping itself as a distinct, advisory-only proposer, separate from the Risk Reviewer to avoid self-review bias; Reviewer agreed the proposer role is structurally necessary but rejected the submission as unapprovable as written — it graded its own necessity instead of using the project's own validation method, and omits mandatory contract sections (Status, Not Responsible For, Permitted Tools, Output Schema, Handoff Contract) plus a confidence label on a self-interested verdict. |
| Agent Risk & Governance Reviewer | Factory | Specialised AI agent | redesign | Both agree an independent adversarial reviewer, kept separate from the Architect and from the run-time Assurance Reviewer, is the right structural pattern against self-review and anchoring bias; the Reviewer found the contract names its own biggest risks (rubber-stamping, hallucination, overlap) without mitigating any of them — no clause-citation requirement on its own findings, no named human escalation/override role, no untrusted-input handling instruction, and no resubmission-diff check. |
| Agent Evaluation Designer | Factory | AI-assisted workflow | redesign | Architect proposed merging test-authoring into the Risk Reviewer's critique since both work from the same fixed 10-category taxonomy and the same input document; Reviewer rejected the merge as a self-review conflict of interest — the agent that finds a risk would also single-handedly judge whether its own test plan covers it — and recommended a separate, lightweight, taxonomy-tagged step sequenced after Risk Reviewer that can never declare an agent "ready." |
| Claude Agent Builder | Factory | AI-assisted workflow | redesign | Both agree Builder should be split into deterministic templating of contract-derived fields plus a narrow, bounded drafting pass for prose, not a freestanding generative agent; Reviewer additionally rejected merging Builder into the Architect (it would collapse the design/implementation separation the project's own docs require), challenged the "pure transcription" framing as understating how interpretive prompt drafting really is, and flagged that Builder's own write permissions into approval-gated directories were never scoped. |
| Stewardship Orchestrator | Operational | Deterministic process | redesign | Both agree routing, case-state, and evidence-preservation are control-flow and guardrail behaviours better built as a deterministic case-routing engine, with only free-text intake classification needing a narrow, human-overridable AI-assisted helper; Reviewer found the submission read as build-ready despite naming its own "premature build" risk, and flagged unresolved identity binding on the human-approval gate, no case-log data-handling policy, and no check against reusing existing case-management infrastructure before building a bespoke store. |
| Investment Operations Context Agent | Operational | AI-assisted workflow | redesign | Architect proposed splitting this three ways into the Orchestrator, Definition & CDE, and Mapping & Lineage, since the evidence-provenance tagging it exists for is already a system-wide obligation; Reviewer rejected the split because the bulk of its scope (trading/settlement lifecycle, TBOR/IBOR/ABOR, NAV, platform architecture) has no home in Definition & CDE's charter and folding it into the Orchestrator would breach that agent's own "route rather than dominate" rule — it should stay one bounded, zero-authority capability with a binding handoff boundary. |
| Definition & CDE Agent | Operational | Specialised AI agent | redesign | Both agree this is genuine AI-eligible evidence-gathering-and-drafting work squarely inside the decision model's "AI may" lane; Reviewer found the contract not yet buildable because it lacks the org's own mandatory Permitted Tools table and Authoritative Sources list — a live gap, since any real glossary/catalog connector this agent integrates with is likely to expose write/delete/status-change tools alongside the read tools it needs — and because its overlap resolutions with Context Agent and Mapping & Lineage are prose recommendations rather than binding handoff rules. |
| Mapping & Lineage Agent | Operational | Specialised AI agent | redesign | Both agree "did the meaning survive the transformation" is genuine AI-eligible semantic comparison with an evidence base distinct from Definition & CDE's and Data Quality's; Reviewer found the granted read footprint (five separate systems at once) unscoped and lacking any prohibition on touching production data values, an unnamed and fallback-free dependency on a deterministic lineage tool, and an unaddressed overlap with Assurance Reviewer's own "inspect lineage consistency" charter. |
| Data Quality Agent | Operational | Specialised AI agent | redesign | Both agree converting an approved business expectation into a candidate control requires genuine synthesis across two other agents' evidence, justifying an agent rather than a fixed transform; Reviewer found an internal contradiction between "consume, don't re-derive" and an independent schema/DDL evidence requirement, a control-owner-proposal function that edges into human-only ownership assignment, and a referenced data-quality-dimension taxonomy that does not yet exist as an approved artefact. |
| Exception & Root-Cause Agent | Operational | Multi-agent workflow | redesign | Architect's redesign correctly rejected a standalone agent with independent multi-system read access as duplicating Mapping & Lineage's work and oversizing the permission footprint, but then dissolved hypothesis-synthesis into an unnamed "workflow" coordinated by the Orchestrator; Reviewer found this breaches the Orchestrator's own "not the primary expert" charter and leaves synthesis with no accountable author, recommending instead a single named, low-permission synthesis agent that consumes a pre-assembled evidence packet rather than gathering its own. |
| Assurance Reviewer | Operational | Specialised AI agent | redesign | Both agree this agent's independent-challenge decision right is categorically distinct from every producer agent and must not be folded into a producer or the Orchestrator, which would recreate the self-review conflict of interest it exists to prevent; Reviewer found the "procedurally gate a case pack" action underspecified as a workflow-control step with no named override role or audit logging, an unscoped read-vs-execute tool footprint, and no committed output schema or coverage policy. |
